# Judge-first 자동 모델 라우팅 최종 분석 보고서

## 1. 결론

이번 실험은 **라우팅과 로컬 학습 파이프라인이 기술적으로 연결됐다는 점은 확인했지만, 라우팅 품질은 제품에 적용할 수준이 아니다.**

- 계획한 80건 중 70건을 완료했다.
- 자동 라우팅은 `gpt-4.1-mini`를 70건 중 62건(88.6%) 선택했다.
- 처음 50건은 Runtime Judge가 선택했고, 이후 20건은 학습된 로컬 라우터가 선택했다.
- 로컬 라우터는 20건 모두 `gpt-4.1-mini`를 선택했다.
- 로컬 구간 20건 중 10건은 실험의 사전 가설 기준으로 성능이 부족한 모델 선택이었다.
- 따라서 이것은 단순한 데이터셋 우연이 아니라 **Judge의 편향된 학습 라벨을 로컬 라우터가 그대로 증폭한 수렴 현상**이다.

현재 결과만 놓고 보면 자동 라우팅을 기본 활성화하면 안 된다. 먼저 학습 라벨 채택 기준과 클래스 불균형 방어를 수정한 뒤 다시 실험해야 한다.

## 2. 실험 범위

| 항목 | 값 |
| --- | --- |
| 워크플로우 | 무RAG 자동 모델 라우팅 블라인드 경제성 실험 |
| Workflow ID | `98000000-0000-0000-0000-000000000002` |

| 계획 | 80개 요청, 10개 단위 중간 기록 |
| 완료 | 70개 요청 |

| 비교군 | 자동 라우팅 / 저가 고정 / 중가 고정 / 고가 고정 |

초기 로컬 환경에는 `jsonschema` 패키지가 설치되지 않아 정상 JSON 출력도 `schema_failed`로 오판되는 문제가 있었다. 해당 의존성을 설치하고 실행 가능한 JSON Schema를 명시한 뒤 새로 시작한 `attempt-04` 결과만 이 보고서에 사용했다. 이전 실패 실행은 분석에서 제외했다.

## 3. 데이터셋 점검

완료된 70건은 15개 업무 범주를 포함한다.

| 기대 난이도 | 건수 | 비율 |
| --- | ---: | ---: |
| 경제형 | 16 | 22.9% |
| 균형형 | 18 | 25.7% |
| 고난도 | 36 | 51.4% |

고난도 요청이 절반을 넘으므로 난이도 분포는 균등하지 않다. 그러나 이 불균형은 `gpt-4.1-mini` 집중을 설명하지 못한다. 고난도 요청이 많으면 오히려 더 강한 모델 선택이 늘어야 하기 때문이다.

실제 고난도 36건의 선택은 다음과 같다.

| 선택 모델 | 건수 |
| --- | ---: |
| `gpt-4.1-mini` | 29 |
| `gpt-4.1` | 4 |
| `gpt-5-mini` | 2 |
| `gpt-5.6-terra` | 1 |

즉 데이터셋의 주제와 난이도 다양성은 존재했지만, 라우터가 이를 모델 다양성으로 변환하지 못했다.

다만 데이터셋이 편향을 보조한 부분은 있다. 모든 요청이 같은 노드의 엄격한 JSON 출력 계약과 공통 제약 문구를 사용했다. Judge와 로컬 분류기가 요청별 난이도보다 `JSON 스키마 준수`라는 공통 특징을 강하게 볼 가능성이 있다. 이것은 보조 원인이며, 근본 원인은 다음 절의 학습 라벨 구조다.

## 5. 로컬 라우터 학습 평가

### 기술적으로 학습됐는가

**그렇다.** 다음 상태가 실제 저장됐다.

- 채택된 Judge 학습 라벨: 50건
- 학습 모드: `local_first`
- 로컬 라우터 처리: 20건
- 학습 아티팩트: `mdeberta_model_choice_online_v1`
- Encoder: `microsoft/mdeberta-v3-base`
- 학습 표본 수: 50건
- 로컬 판단 기준 확신도: 0.78
- 로컬 판단의 관측 확신도: 약 0.826

즉 “학습 코드가 실행되지 않았다”는 문제는 아니다.

### 잘 학습됐는가

**아니다.** 로컬 라우터는 요청 난이도를 일반화한 것이 아니라 Judge가 많이 선택한 모델을 외운 상태에 가깝다.

Judge가 만든 첫 50개 라벨은 다음과 같이 치우쳤다.

- `gpt-4.1-mini`: 42건(84%)
- 나머지 4개 모델: 합계 8건
- 사용 가능한 나머지 6개 모델: 라벨 0건

학습 아티팩트의 모델별 bias도 이를 그대로 보여준다.

| 모델 | 학습 bias |
| --- | ---: |
| `gpt-4.1-mini` | 1.7784 |
| `gpt-4.1` | 0.1569 |
| `gpt-5-mini` | -0.0800 |
| `gpt-4o-mini` | -0.1104 |
| `gpt-5.6-terra` | -0.1225 |
| 선택 이력이 없는 모델들 | 약 -0.2704 |

`gpt-4.1-mini`의 기본 가중치가 다른 모델보다 압도적으로 커졌다. 그래서 입력 의미가 달라도 비슷한 약 0.826의 확신도로 같은 모델을 선택했다. 서로 다른 요청에서 확신도가 거의 동일하다는 점도 입력별 판별보다 다수 클래스 bias가 지배했다는 증거다.

### 로컬 구간의 실제 성적

| 항목 | Judge 구간 1~50 | Local 구간 51~70 |
| --- | ---: | ---: |
| 자동 라우팅 평균 품질 | 77.28 | 74.45 |
| 품질 계약 통과율 | 60.0% | 45.0% |
| 평균 LLM 실행 시간 | 8.44초 | 4.18초 |
| 라우팅 Judge 비용 | $0.201488 | $0 |
| 사전 가설상 과소 성능 선택 | 별도 전체 집계 | 20건 중 10건 |

로컬 전환으로 Judge 비용과 시간은 줄었지만 품질과 계약 통과율도 떨어졌다. 따라서 현재 로컬 학습은 비용 절감에는 기여했지만, 올바른 모델 선택을 학습했다고 볼 수 없다.

## 6. 라우팅 적합성

데이터셋 작성 시 각 요청에 적합 모델, 부족한 모델, 과도한 모델을 미리 정의했다. 이 가설로 자동 선택을 판정한 결과는 다음과 같다.

| 판정 | 건수 | 비율 |
| --- | ---: | ---: |
| 적합 | 34 | 48.6% |
| 성능 부족 | 29 | 41.4% |
| 판정 불가 | 7 | 10.0% |

로컬 라우터 구간만 보면 적합 10건, 성능 부족 10건이다. 모델 선택 성공률을 넓게 잡아도 50%에 불과하다. 특히 고난도 요청에서 mini를 선택한 사례가 집중돼 시연 안정성과 실제 운영 품질 모두 위험하다.

### 70건 누적

| Arm | 제품 비용 | 평균 품질 | 품질 계약 통과율 | 평균 LLM 실행 시간 |
| --- | ---: | ---: | ---: | ---: |
| 자동 라우팅 | $0.267553 | 76.47 | 55.7% | 7.22초 |
| 저가 고정 | $0.011908 | 61.94 | 1.4% | 2.43초 |

| 고가 고정 | $1.492765 | 89.81 | 95.7% | 12.99초 |

자동 라우팅 비용에는 첫 50건의 Runtime Judge 비용 $0.201488이 포함된다. 별도의 블라인드 품질 평가 비용 $0.108582는 모든 Arm을 평가하기 위한 실험 비용이므로 제품 비용 비교에서는 제외했다.

### 해석

- 고가 고정 대비 자동 라우팅은 비용을 약 82.1% 줄였지만 품질은 13.34점 낮았다.
- 중가 고정 대비 자동 라우팅의 **작업 모델 비용만** 보면 약 62.3% 저렴하다.
- 그러나 Runtime Judge 비용까지 포함하면 자동 라우팅은 중가 고정보다 약 52.7% 비싸다.
- 자동 라우팅은 중가 고정보다 평균 실행 시간이 약 69.8% 길고 품질 계약 통과율은 40%p 낮다.
- 로컬 전환 후에는 Judge 비용이 사라져 경제성이 개선되지만, 평균 품질은 중가 고정 87.90 대비 74.45로 13.45점 낮다.

따라서 이번 실험에서는 자동 라우팅이 고가 고정보다 싸다는 점은 확인했지만, **중가 고정 대비 비용·품질의 우월성은 입증하지 못했다.** 초기 50건은 Judge 비용 때문에 더 비싸고, 이후에는 비용은 싸지만 품질 손실이 크다.

## 8. 근본 원인

### 8.1 Judge 선택이 학습 정답으로 바로 사용됨

현재 학습은 Runtime Judge가 선택한 모델을 정답 라벨로 사용한다. 실행 후 Schema, workflow 성공, fallback 여부 같은 계약은 확인하지만, 독립 품질 Judge가 측정한 실제 품질은 학습 라벨 채택에 사용하지 않는다.

그 결과 `gpt-4.1-mini`가 JSON을 정상 반환하면 품질이 60~70점대여도 성공 라벨로 학습된다. Judge의 초기 편향이 교정되지 않고 누적된다.

### 8.2 클래스 불균형 방어가 없음

50개 학습 라벨 중 42개가 같은 모델인데도 그대로 학습한다. 모델별 표본 상한, 클래스 가중치, 균형 샘플링, 최소 다양성 조건이 없다. 온라인 분류기의 bias가 다수 모델 쪽으로 커지는 것은 현재 수식상 자연스러운 결과다.

### 8.3 로컬 확신도가 제대로 보정되지 않음

로컬 구간의 확신도는 요청 종류와 무관하게 약 0.826으로 거의 동일했다. 이 값은 독립 검증 세트에서 측정한 정답 확률이 아니라 편향된 학습 점수의 softmax 결과다. 따라서 0.78 임계값을 넘었다고 실제로 신뢰할 수 있는 판단은 아니다.

### 8.4 노드 공통 계약이 요청별 난이도보다 강함

모든 요청이 같은 JSON Schema와 공통 제약을 사용한다. Runtime Judge의 선택 사유도 `strict_output_reliability`에 집중됐다. 요청별 추론 난이도보다 “JSON을 안정적으로 반환할 모델”이 우선되면서 하나의 안전한 mini 모델로 몰렸다.

## 9. 개선 우선순위

### P0. 편향된 로컬 정책 활성화 차단

- 한 모델이 학습 라벨의 70% 이상이면 `local_first` 전환을 보류한다.
- 모델 선택 entropy 또는 최소 유효 모델 수를 전환 조건에 추가한다.
- 현재처럼 42/50이 같은 모델이면 계속 Judge를 사용하되, 원인을 상태와 trace에 표시한다.

### P0. 학습 라벨 채택에 실제 품질 신호 연결

- Schema/workflow 성공만으로 라벨을 채택하지 않는다.
- 표본 품질 평가 또는 중가 기준 응답과의 품질 차이가 허용 범위 안일 때만 채택한다.
- 품질 평가 비용이 부담되면 모든 실행이 아니라 모델·업무 범주별 대표 표본만 평가한다.

### P1. 클래스 불균형 보정

- 모델별 학습 표본 상한 또는 역빈도 가중치를 적용한다.
- 라벨이 없는 모델을 무조건 선택하게 만들 필요는 없지만, 한 모델의 bias가 입력 특징을 압도하지 못하게 해야 한다.
- 학습 전후에 모델 분포, entropy, bias 범위를 진단 지표로 저장한다.

### P1. 확신도 보정과 보류 경로

- 학습에 사용하지 않은 holdout 표본으로 confidence threshold를 정한다.
- 입력별 최고 확률과 2위 확률 차이가 작으면 Judge로 넘긴다.
- 모든 입력의 confidence가 비슷하면 모델 붕괴 신호로 판단한다.

### P1. 요청 난이도와 고정 노드 계약 분리

- JSON Schema 필요 여부처럼 모든 요청에 같은 값은 후보 제거 조건으로만 사용한다.
- 모델 선택 점수는 요청 내용의 위험도, 다중 조건, 모호성, 필요한 추론 깊이처럼 매 요청 달라지는 특징에 더 큰 비중을 둔다.

| 경제성이 입증됐는가? | 고가 고정 대비 절감은 확인했지만 중가 고정 대비 우위는 입증하지 못했다. |
| 남은 10건을 그대로 실행할 가치가 있는가? | 낮다. 현재 정책에서는 mini 선택이 반복될 가능성이 높다. 개선 후 새 실험으로 다시 시작하는 편이 타당하다. |

이번 실험의 가장 중요한 성과는 “로컬 라우터가 작동한다”가 아니라 **현재 학습 방식에서는 Judge 편향이 자동으로 강화된다는 사실을 데이터로 확인한 것**이다. 다음 실험은 P0 개선을 적용한 새 정책과 새 학습 아티팩트로 처음부터 수행해야 한다.

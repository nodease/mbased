# Judge-first 자동 모델 라우팅 수동 테스트 입력 세트

Status: Manual Test Dataset

## 사용 방법

각 JSON을 배포된 `Judge-first 자동 모델 라우팅 경제성 실험` workflow의 webhook 입력으로 한 건씩 보낸다.

- 입력 필드: `customerTier`, `message`
- 권장 순서: 아래 번호 순서 그대로가 아니라 1~24를 섞어서 실행한다.
- 확인할 trace: `selected_model`, `decision_source`, `judge_called`, `reason_code`, `fallback_model`
- 이 문서의 난이도는 **기대 관찰 기준**이다. 특정 모델 하나가 반드시 정답이라는 뜻은 아니다.

## 분포

| 작업 수준 | 건수 | 목적 |
| --- | ---: | --- |
| 단순 | 8 | 짧은 안내, 단일 사실 확인, 형식화 |
| 중간 | 8 | 조건 결합, 우선순위 판단, 여러 단계 안내 |
| 고난도 | 8 | 보안, 법무, SLA, 금전, 장애 복구처럼 잘못된 답변 비용이 큰 판단 |

## 입력 세트

### 01. 단순 - 다운로드 위치 안내

```json
{
  "customerTier": "startup",
  "message": "지난달 청구서를 어디에서 다운로드하는지 알려주세요."
}
```

관찰 기준: 짧고 직접적인 사용 안내. 불필요한 고성능 모델 선택 여부를 확인한다.

### 02. 고난도 - 개인정보 유출 가능성

```json
{
  "customerTier": "enterprise",
  "message": "외부 협력사에 전달한 CSV에 고객 이메일과 전화번호가 포함됐을 가능성이 있습니다. 즉시 해야 할 조치, 조사 범위, 고객 안내 전 확인 사항을 우선순위대로 정리해 주세요. 사실이 확정되지 않은 내용은 단정하지 마세요."
}
```

관찰 기준: 개인정보, 외부 공유, 불확실성, 단계적 대응을 함께 판단해야 한다.

### 03. 중간 - 팀원 초대 실패

```json
{
  "customerTier": "business",
  "message": "결제는 완료됐는데 팀원 초대가 계속 실패합니다. 초대 메일도 오지 않습니다. 관리자가 먼저 확인할 항목과 사용자에게 안내할 내용을 나눠서 알려주세요."
}
```

관찰 기준: 원인 가설과 조치 순서를 구분하는 지원 요청이다.

### 04. 단순 - 비밀번호 재설정

```json
{
  "customerTier": "startup",
  "message": "비밀번호를 잊었습니다. 재설정 방법을 세 단계로 알려주세요."
}
```

관찰 기준: 짧은 절차 안내다.

### 05. 고난도 - SLA와 보상 검토

```json
{
  "customerTier": "enterprise",
  "message": "어제 47분 동안 주문 생성 API 오류가 발생했고 일부 고객은 주문을 완료하지 못했습니다. 계약상 SLA 위반 가능성과 크레딧 보상 요청 가능성이 있습니다. 장애 대응, 증빙 수집, 고객 공지, 보상 승인 판단을 섞지 말고 구분해서 초안을 만들어 주세요."
}
```

관찰 기준: 장애, 계약, 금전 보상, 고객 커뮤니케이션을 분리해야 한다.

### 06. 중간 - 월간 사용량 보고


관찰 기준: 간단한 분석과 우선순위가 필요하다.

## 실행 후 빠른 확인 기준

| 확인 항목 | 기대 모습 |
| --- | --- |
| 단순 요청 | 불필요하게 항상 최상위 모델만 선택하지 않음 |
| 중간 요청 | 단순 안내보다 한 단계 높은 추론·작성 능력이 필요한 모델을 선택할 여지가 있음 |
| 고난도 요청 | 보안, 금전, 계약, 장애처럼 실패 비용이 큰 요청에서 보수적 모델 선택과 위험 인식이 나타남 |
| trace | `decision_source`, `judge_called`, `selected_model`, `reason_code`가 기록됨 |
| fallback | 최초 호출 실패가 있을 때만 fallback 모델이 기록됨 |

## 주의

현재 Judge-first 정책은 로컬 router artifact가 준비되지 않은 상태라면 요청마다 Runtime Judge를 호출할 수 있다. 따라서 같은 입력을 반복 실행해도 후보 모델과 Judge 판단에 따라 선택이 달라질 수 있다. 수동 테스트에서는 한두 건의 선택보다, 단순·중간·고난도 묶음 전체에서 선택 경향과 품질을 함께 확인하는 것이 좋다.

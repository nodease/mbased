# 모델 라우팅 검증용 고객 티켓 수동 데이터셋

Status: Active

## 대상 워크플로우

- 이름: `모델 라우팅 검증용 고객 티켓 처리`
- 입력 계약: `customerTier`, `message`
- 목적: 같은 LLM 노드에 단순 안내, 일반 조사, 복합·고위험 판단을 섞어 보내 모델 선택이 요청별로 달라지는지 수동 확인한다.
- payload 파일: `docs/demo/model-routing-ticket-manual-payloads.jsonl`

JSONL 파일의 각 줄은 독립적인 webhook payload다. 한 줄씩 복사해 실행한다. 줄 전체를 배열로 감싸서 보내지 않는다.

## 기대 분포

아래 기대 수준은 특정 모델명을 강제하지 않는다. 실제 선택 모델은 현재 사용자가 사용할 수 있는 credential, 후보 모델 카탈로그, 운영 성적과 fallback 상태에 따라 달라질 수 있다.

## 수동 확인 항목

각 실행 후 LLM 노드 상세에서 다음을 기록한다.

1. 실제 선택 모델
2. Judge 호출 여부와 판단 근거
3. fallback 발생 여부와 실제 대체 모델
4. 출력 JSON Schema 통과 여부
5. 후속 변수 추출과 조건 분기 성공 여부
6. 비용, 실행 시간, 전체 토큰

정상적인 결과는 모든 요청이 서로 다른 모델을 쓰는 것이 아니다. 비슷한 능력이 필요한 요청은 같은 모델을 사용할 수 있다. 다만 경제형·균형형·고성능형 사이에 선택 모델이나 모델군 차이가 전혀 없으면 후보 프로필, Judge 입력, credential 후보 목록과 라우팅 trace를 점검해야 한다.
